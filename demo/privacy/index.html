The package

@fluritheme/spider does not send analytics, visitor data or installation reports. It runs locally on the website where you install it. This website’s measurements are separate from the package.

This website

We count successful public HTML page requests to understand interest in Spider and improve this site. Cloudflare Workers aggregates these into daily totals in a separate Cloudflare D1 database created with EU jurisdiction. Only the UTC date, a public page path, a broad referral category, count and update time are stored. Query strings, full referrer URLs, IP addresses, user agents and visitor identifiers are not stored in this analytics database.

We do not use analytics cookies, tracking scripts or fingerprinting. Requests carrying Do Not Track or Global Privacy Control are excluded. Common bots, prefetches, errors, assets, the dashboard and API are excluded. Filtering is approximate; counts represent requests including repeat visits, not unique people.

Retention & access

Daily traffic totals are kept for the latest 90 UTC calendar days. A daily retention job removes older rows and expired administrator sessions. Hosting backups follow Cloudflare D1’s Time Travel retention. Only authenticated administrators can access the dashboard and exports.

Administrators use an essential, secure, HTTP-only session cookie expiring after eight hours. Only a hash of the random session token is stored. Login and API endpoints use Cloudflare rate limits; the daily hashed network address used for that limit is separate from analytics and is not stored in D1.

One private traffic dashboard

Aggregate traffic is viewed at fluri.xyz/dashboard, alongside the main site, Winter and Grinch. It reports page views and broad referrer categories, without npm download statistics. Earlier Spider traffic remains available. Public README badges can still show package-download counts from npm; these do not identify website visitors.
